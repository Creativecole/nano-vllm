# Benchmark Methodology

The attention benchmark path is intentionally separate from the full `LLM.generate` path.

## Decode Benchmark

`benchmarks/bench_attention_decode.py` isolates single-token paged decode attention:

- builds random Q/K/V tensors with Qwen3-4B head counts
- packs dense K/V into paged KV cache
- runs `torch_paged` as correctness reference
- runs the selected backend
- reports p50/p95 latency, tokens/s, max absolute error, and max relative error

This is a kernel/backend benchmark. It is not an end-to-end serving benchmark.

## Prefill Benchmark

`benchmarks/bench_attention_prefill.py` compares prefill attention paths:

- `torch_sdpa`
- `flash_attn`

Triton flash-style prefill is a future extension. It should not be claimed as implemented until it is
present and measured.

## Result Policy

- Do not report numbers that are not generated by checked-in scripts.
- Keep correctness error next to latency numbers.
- Treat `torch_paged` as the reference path for decode.
- Treat E2E `flash_attn` generation as stable runtime until custom decode is wired and tested.
